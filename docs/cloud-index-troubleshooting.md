# 云端代码索引失败排查与重建

本文说明控制台中“索引中”“索引失败”“索引可用”等状态的含义，以及失败记录清理、云端索引删除和重新建立索引的正确方式。

## 先区分两个状态维度

一个仓库分支可能同时存在以下两类状态：

1. **已发布索引是否可用**：最后一次成功发布的快照仍可被代码检索使用。
2. **最近一次同步任务是否成功**：新的全量或增量任务可能正在构建，也可能已经失败。

因此，“索引更新失败，但旧索引仍可用”并不矛盾。控制台会显示黄色失败状态，并保留旧快照的删除入口。

## 失败后会不会自动重试

- Relay 中已经变为 `failed` 或 `timed_out` 的任务是终态，**同一个任务不会在服务端恢复网络后继续执行**。
- 恢复网络、刷新控制台、再次向 Agent 提自然语言问题，均不应视为可靠的整任务重试方式。
- 索引文件由本地 VS Code/MCP 客户端读取和上传，服务端无法脱离客户端自行重建整个仓库。
- 客户端正常在线时可能通过文件监听发起后续增量同步，但对于一次已经终止的全量/增量任务，推荐显式重新加载客户端来创建新任务。
- 平台每日索引配额用尽时，当前任务会失败并停止；支持自动恢复的新版索引客户端保持运行时，会按 Relay 返回的重置等待时间创建一个新任务。客户端已经关闭或版本不支持该策略时，需要在配额恢复后重新启动客户端。
- 第三方模型服务的余额、预算或通用 `quota exceeded` 不属于平台每日索引配额；修复第三方计费问题后应创建新的同步任务，不能等待平台配额重置。

### 推荐的重新建立索引步骤

1. 根据控制台的失败分类和“原始错误详情”修复根因。
2. 在 VS Code 执行 **Developer: Reload Window**，或重启配置了 LCE 的 MCP 客户端。
3. 保持目标仓库打开，并等待客户端重新扫描、比较 manifest 和上传待索引文件。大型仓库所需时间会更长。
4. 让 Agent 调用 `codebase_index_status`，或在控制台“索引管理”中确认状态重新进入“索引中”，最终变为“索引可用”。

如果修复原因并重启客户端后仍没有新任务，请检查 MCP 进程是否启动、API Key/组织上下文是否正确，以及请求日志中是否出现 `codebase_index` 调用。

## 每日索引配额与失败重试计费

每日索引字节配额衡量送入索引流程的文件内容，不等同于控制台中已成功发布的索引大小。因此，“已用 2 GiB”不表示当天已经成功生成或上传了 2 GiB 的可用索引。

Relay 对同一租户、同一索引 root、同一路径和同一内容哈希实行当天幂等计费：同一份内容因第三方故障、网络失败或新任务重放时，只计费一次；文件内容改变或使用不同 root 时会重新计费。配额判断与计费记录在服务端原子完成，超限拒绝不会把该批文件标记为已计费。

修复部署前已经由重复失败请求累计的当日用量，服务端无法仅凭计数器安全判断哪些记录应退款，因此不会自动回退。应等待当日配额重置，或由管理员确认后调整对应租户的配额；修复部署后的相同内容重试不会继续重复累加。

## “清理失败记录”和“删除云端索引”的区别

### 清理失败记录

适用于红色或黄色的失败任务卡片。

- 只删除该 root 下状态为 `failed` / `timed_out` 的 Relay 任务记录及其级联暂存清单。
- 不删除 `index_workspaces`、`indexed_files` 和已经发布的 LCE 云端快照。
- 如果第一次索引就失败，清理后该失败项会从列表消失。
- 如果增量更新失败但旧快照仍可用，清理后页面会回到旧快照的“索引可用”状态。
- 清理动作本身**不会触发重新索引**；修复根因后仍需重新加载 VS Code 或重启 MCP 客户端。

### 删除云端索引

这是破坏性操作，用于确实不再需要某个仓库/分支索引的场景。

- 删除 LCE 已发布云端快照。
- 删除 Relay 中对应的 workspace、文件清单和任务记录。
- 删除后代码检索不可再使用该快照；若还需要检索，必须按上面的步骤重新建立索引。
- 有运行中的索引任务时，清理和删除都会返回冲突，必须等待任务结束或超时回收后再操作。

组织索引的上述操作仅允许组织所有者执行。

## 常见异常及处理策略

| 场景 / 原始错误示例 | 通常表现 | 是否会自动恢复 | 建议处理 |
|---|---|---|---|
| `remote-index 502`、`Bad gateway`、Cloudflare 502 | 当前任务失败；已有旧快照时旧快照仍可用 | 终态任务不会自行续跑 | 等远端索引服务恢复，随后重新加载 VS Code 或重启 MCP 客户端 |
| 第三方模型 `402`、`insufficient balance`、计费异常 | 需要调用该模型的索引阶段失败 | 补余额后旧任务不会自行续跑 | 补充余额或切换可用模型配置，验证后重启客户端 |
| 第三方模型 `401` / `403`、API Key 无效 | 索引请求失败 | 不会 | 修正 URL、API Key、模型名和权限，然后重启客户端 |
| 第三方模型 `429` / rate limit | 当前批次或任务失败 | 不保证 | 等待限流窗口结束、降低并发，然后重启客户端 |
| `daily index quota exceeded` / `index_quota_exceeded` | 上传批次被服务端配额拒绝，当前任务会失败 | 支持自动恢复的新版客户端会在重置后创建新任务；旧任务不会续跑 | 保持新版客户端运行；客户端已关闭或版本不支持时，在配额恢复后重新启动客户端 |
| `manifest exceeds 100000 files` | `start` 请求在创建任务前被拒绝，因此控制台不一定出现新的失败卡片 | 不会 | 忽略依赖、构建产物和生成目录，或拆分仓库后重启客户端 |
| `manifest file size is invalid`、`file exceeds the 524288 byte limit`，或单文件超过 512 KiB | manifest/start 或上传批次被拒绝；若任务已创建，客户端应上报失败 | 不会 | 忽略/拆分大文件后重启客户端 |
| `index job heartbeat timed out` | 10 分钟未收到有效心跳后任务变为超时失败 | 网络恢复不会续跑该任务 | 检查本机网络、VS Code/MCP 进程和服务端连通性，然后重启客户端 |
| `connection refused`、`network is unreachable`、`i/o timeout` | 请求失败，后续可能转为失败或心跳超时 | 不保证 | 恢复网络后显式重启/重新加载客户端 |

> Rerank 通常发生在检索阶段，而代码索引主要依赖 Embedding。若只配置的 Rerank 服务余额不足，是否影响索引取决于实际服务调用链；应以控制台中的原始错误和请求日志为准。

## 为什么文件上限错误有时没有失败卡片

文件数量和 manifest 中声明的单文件大小会在 `start` 创建任务之前校验。校验失败时没有可持久化的运行任务，因此状态接口可能继续显示旧快照，或显示尚未开始，而不是新增一条失败任务。此时错误会直接返回给 MCP 客户端，应从 Agent/MCP 输出和请求日志定位。

上传阶段才发现的内容大小、配额或远端模型错误发生在任务创建之后；客户端应调用失败上报，控制台随后会展示失败任务。若客户端断网到无法上报，Relay 会在心跳超时后把任务标记为 `timed_out`。

## 提交服务端问题时需要的信息

确认不是本地配置或第三方服务问题后，请提供：

- 控制台中的 `root_id`、workspace 名称和分支；
- 失败发生的准确时间和时区；
- 展开的原始错误详情；
- 请求日志 ID、HTTP 状态码和相关工具名；
- VS Code/MCP 客户端版本；
- 使用个人索引还是组织索引；
- 第三方模型类型、服务商和模型名（不要提交 API Key 等密钥）。

这些信息可用于区分客户端断连、Relay 配额/校验、远端索引服务故障和第三方模型故障。
