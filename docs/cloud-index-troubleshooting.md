# 云端代码索引失败排查与重建

本文说明索引失败后的重试、清理和重建策略。状态页展示的是服务端任务与已发布快照；真正的仓库文件仍由能够读取本地仓库的索引客户端扫描和上传。

## 状态与旧快照

一个仓库分支同时有两个维度：

1. 最近一次同步任务可能正在运行、成功、失败或心跳超时；
2. 上一次成功发布的快照可能仍然可检索。

因此，“本次更新失败”不一定意味着旧索引不可用。清理失败任务也不会自动删除仍可检索的旧快照。

## 哪些错误会自动重试

错误必须按类型处理，而不是按文案猜测：

- **瞬时错误**：网络中断、连接重置、上游超时、HTTP 429 和服务端 5xx。客户端可做有上限的指数退避重试；达到重试预算后暂停，避免无限消耗资源。
- **永久错误**：第三方模型服务余额/预算不足、无效或无权限的密钥、确定性的请求参数或编码错误、仓库超过当前服务端限额。当前同步应立即停止自动重试，等待配置、余额、仓库内容或服务限额发生变化。
- **平台每日索引配额**：当前 Relay 任务会失败并停止，不进行快速重试，也不消耗普通瞬时错误的重试预算。支持自动恢复的新版索引客户端保持运行时，会按照 Relay 返回的重置等待时间创建一个新的同步任务；客户端已经关闭或版本不支持该策略时，需要在配额恢复后重新启动客户端。
- Relay 中已经进入 `failed` 或 `timed_out` 的任务是终态；任何自动恢复都是创建新任务，不会让原任务从终态继续运行。

再次自然语言提问、刷新网页或只清理失败记录都不是可靠的整任务重试触发器。

## 每日索引配额与失败重试计费

每日索引字节配额衡量送入索引流程的文件内容，不等同于控制台中已成功发布的索引大小。因此，“已用 2 GiB”不表示当天已经成功生成或上传了 2 GiB 的可用索引。

Relay 对同一租户、同一索引 root、同一路径和同一内容哈希实行当天幂等计费：同一份内容因第三方故障、网络失败或新任务重放时，只计费一次；文件内容改变或使用不同 root 时会重新计费。配额判断与计费记录在服务端原子完成，超限拒绝不会把该批文件标记为已计费。

修复部署前已经由重复失败请求累计的当日用量，服务端无法仅凭计数器安全判断哪些记录应退款，因此不会自动回退。应等待当日配额重置，或由管理员确认后调整对应租户的配额；修复部署后的相同内容重试不会继续重复累加。

## 如何手动重新建立索引

1. 根据失败分类和原始错误详情修复根因。
2. 让一个**能够读取目标仓库**的索引客户端重新初始化该仓库会话并创建新同步；如果客户端没有“重试索引”操作，重新连接或重新初始化该仓库会话。
3. 保持客户端能够持续访问仓库，等待重新扫描、比较清单和上传。大型仓库需要更长时间。
4. 使用客户端提供的索引状态能力，或在控制台“索引管理”中确认新任务进入“索引中”并最终变为“索引可用”。

如果没有出现新任务，请检查索引客户端进程、仓库访问权限、API Key/组织上下文和 Relay 请求日志中是否出现新的索引同步调用。

## 更换 Embedding 配置的影响

Embedding 供应商、Base URL、模型、向量维度、输出参数或影响入库向量的前缀发生变化时，旧向量空间与新查询不再兼容。

保存这类变更时，系统会要求管理员确认，并清除平台当前项目的 Relay 索引状态、LCE 云端向量索引和 Embedding 缓存。旧索引会立即失效，必须由各仓库的索引客户端重新读取和上传源文件。系统无法仅凭后台配置自行读取用户本地仓库，因此不会自动重建所有项目。

切换前应确认新供应商的密钥、余额、限流、输出维度和可用性，并为重新索引预留第三方额度及平台配额。以下变更不应使现有向量索引失效：

- 仅轮换 API Key，且供应商、Base URL、模型和向量参数均未变化；
- 仅修改 Rerank；
- 仅修改提示词增强配置。

如果保存时提示仍有索引或检索事务执行，说明切换尚未发生、旧索引也未被本次请求清除。等待在途事务结束后再重试。

## “清理失败记录”和“删除云端索引”

### 清理失败记录

- 删除失败或心跳超时任务及其暂存数据；
- 保留已发布快照、工作区和已索引文件记录；
- 不触发重新索引；
- 首次索引失败时，清理后失败项会消失；增量失败但旧快照可用时，页面会回到旧快照状态。

### 删除云端索引

- 删除指定仓库/分支的已发布快照和 Relay 元数据；
- 后续检索不可用，直到索引客户端完成一次新的全量同步；
- 仅在确实需要移除或彻底重建索引时使用。

## 常见故障策略

| 故障类型 | 典型表现 | 自动重试 | 处理方式 |
| --- | --- | --- | --- |
| Embedding 向量空间已变化 | 云端返回 `cloud embedding space changed`，要求先清除 tenant root | 否 | 使用控制台“重置云端索引”完整删除对应 root，再重启索引客户端创建新同步；只清理失败记录无效 |
| 第三方余额或预算不足 | 第三方返回 billing、credit、insufficient balance 等错误 | 否 | 充值或更换有效凭据后创建新同步；不要把第三方的通用 `quota exceeded` 当成平台每日索引配额 |
| 平台每日索引字节配额已用尽 | Relay 返回 `index_quota_exceeded`、已用/上限和重置等待时间 | 到重置时间创建新任务 | 保持支持自动恢复的新版索引客户端运行；客户端已关闭或版本过旧时，在配额恢复后重新启动客户端 |
| 密钥无效或无权限 | 供应商返回认证/授权错误 | 否 | 修正密钥和权限后创建新同步 |
| 确定性请求/编码错误 | 供应商拒绝输入、模型参数或字符编码 | 否 | 修正输入处理或配置后创建新同步 |
| 网络中断、超时、连接重置 | 客户端或上游暂时不可达 | 有上限 | 网络恢复后观察客户端退避重试；预算耗尽则创建新同步 |
| 限流或上游 5xx | 429、网关错误、服务过载 | 有上限 | 等待退避；持续失败时检查供应商状态和容量 |
| 仓库超过服务端文件数量/大小限制 | manifest 或上传批次被拒绝 | 否 | 依据原始错误与当前服务配置缩小索引范围或调整服务端限额 |
| 心跳超时 | 任务长时间无客户端心跳 | 原任务否 | 检查客户端进程和网络，修复后创建新同步 |
| 服务端内部故障 | Relay/LCE/数据库错误 | 视状态码而定 | 先恢复服务；已终止任务仍需客户端创建新同步 |

## 排错信息要求

控制台应同时展示：失败分类、责任侧、建议动作和经过裁剪的原始错误详情。运维排查时还应结合 Relay 请求日志、LCE 日志、供应商响应状态以及当前运行时限额配置，不能依赖写死在前端文案中的数字或单一客户端名称。
