# 硬编码治理规则

本项目不把“所有字面量”都视为错误。硬编码审查按以下边界执行：

- **协议常量**可以固定：MCP/JSON-RPC 字段、工具名、数据库契约版本、状态枚举、加密上下文等必须由契约测试钉住。
- **产品身份常量**可以集中固定：软件包名、受支持供应商标识等必须只有一个来源，不能散落复制。启动命令、包执行器及其参数不是产品身份，必须由部署配置提供。
- **运行时策略**必须配置化或集中化：服务地址、外部 registry/site URL、超时、重试预算、限额、并发和轮询策略不得在多层各自写死。
- **用户可见说明**必须能力化：不得假设某个 IDE、编辑器、宿主、包管理器或固定命令；不得在前端写死可能由服务端配置改变的限额数字。
- **供应商预设**必须集中：官方 endpoint 和默认模型属于可维护预设，UI、路由和校验逻辑应引用同一注册表。

新增代码时，若引入运行时数字或外部地址，应优先加入统一配置模块及 `.env.example`，并补充边界测试。若确属协议或安全上限，应使用有语义的命名常量和注释说明不可配置的原因。

静态守卫会扫描页面、翻译、配置生成器和排错文档，阻止重新引入指定编辑器/IDE、固定启动命令、散落的服务限额与重复运行策略。部署文件中的默认值属于显式运维策略，但浏览器可见的 `NEXT_PUBLIC_*` 必须在镜像构建阶段传入，不能只写在容器运行环境中。

## 当前策略所有者

- `lib/client-runtime-policy.ts`：浏览器轮询、刷新、提示反馈等客户端节奏。
- `lib/server-runtime-config.ts`：Relay/站点/软件包 registry 地址、代理超时、鉴权生命周期、SMTP、支付、PostgreSQL、Redis、时区与服务端响应边界。
- `lib/time-policy.ts`：IANA 时区自然日边界；不得用固定 UTC 偏移替代，因为部署时区可能变化且部分时区有夏令时。
- `lib/quota-policy.ts`：管理接口允许写入的配额安全上限。这些是防止异常输入和数值膨胀的领域安全边界，不是套餐文案；页面不得复制数字。
- `lib/model-provider-presets.ts`：供应商协议预设、向量维度与 API Key 池安全容量；翻译和组件通过参数展示，不能各自复制。
- `lib/auth-provider-presets.ts`：OAuth 供应商协议端点；这些属于集成身份，不是可调超时，但仍禁止在鉴权流程中散落复制。

宿主专属的 MCP 启动器配置（例如可执行文件及参数）保留在开发者本机，不提交 `.mcp.json` 或 `.codex/config.toml`，避免仓库替所有环境决定包执行器、命令来源或 `latest` 版本。

全局审计不是追求“代码中没有数字”，而是要求每个数字有明确归属：协议/安全不变量由单一模块命名并测试，可调运行策略由环境配置集中加载，用户文案只引用实际能力或运行时返回值。
